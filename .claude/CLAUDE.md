# Games-Web

The hub at https://games.infinitetoken.com, created 2026-10-17. It lists the Tastic games (CardTastic, Solitaire until 2026-11-11, Hangman, DuelTastic, LightCycles and Snake until 2026-11-11, PuckTastic, BoxHockey until 2026-11-11), Swirlio under More to Play, the ones coming soon, and the 6502 cartridges (A.C. Wright's Wizards Lab, then HexFleet, Snake and TrailDuel; Pong is hidden for now), hosts the one privacy policy, terms of use and support page for all of them, and puts every Tastic game's web version on this one origin at `/<slug>/`. The point of the single origin: localStorage is per origin, so only on one origin can the web games share player profiles the way the iOS apps do through the App Group `group.com.infinitetoken.tastic` (the web side of that lives in `@tastic/profile`). Before this, each game had its own subdomain (`<slug>.infinitetoken.com`); those now redirect here, from each game's own `vercel.json`.

## Commands

```bash
npm run dev        # Nuxt dev server (also `games-web` in ~/Developer/.claude/launch.json)

```

## Stack and template

- Built from the `<Name>-Web` sibling template (JayDeaton-Web, GraPDF-Web, SnaPDF-Web, TrimBox, MapFolio): Nuxt 4 with `srcDir: 'src'`, Tailwind v4 through `@tailwindcss/vite`, the same eslint, vitest, tsconfig, CI, and deploy files. Keep that tooling converged with the siblings. **The look follows InfiniteToken-WWW instead** (2026-10-22, see Look below): it's the company's games site, not a page of jaydeaton.com. The accent is Tailwind's **indigo**, as on www.
- **Deliberate differences from the template:** no `@vite-pwa/nuxt` (a service worker scoped to `/` would also control the proxied games and could answer their navigations with this site's cached pages), so no `usePwa` either; no `@nuxtjs/color-mode` or safe-area shell (dark only, the window scrolls, as on www); and the class strings live in `src/constants/styles.ts` because four pages share them.
- Content is in `src/constants/site.ts` (`SITE`, `TASTIC_GAMES`, `CARTRIDGES`, `EMULATOR`); pages only render it. `TASTIC_GAMES` is HexFleet first, then the Tastic games alphabetically with Hangman ahead of CardTastic, since it's becoming AlphaTastic (Jay, 2026-11-20; it was plain alphabetical from 2026-11-13, when Hangman sitting second, one move from alphabetical, grated). The preview card's icons, www, jaydeaton.com and the profile README follow it, with Swirlio after the Tastic games, and `app.test.ts` pins it and the card's icons; keep a new Tastic game in its alphabetical place among the Tastic games. It is also the single source for the proxy routes and the prerender list in `nuxt.config.ts`, so adding a game is one entry there plus its image.
- Copy rules: Title Case headings, one-word buttons (Play, Source, Home), no em or en dashes anywhere (tests enforce it for `site.ts` and the rendered privacy, terms and support pages, which also may not use a spaced hyphen as a dash).

## How the games are served

- `src/utils/vercelRoutes.ts` turns `TASTIC_GAMES` into Vercel Build Output API routes: `^/<slug>$` 308s to `/<slug>/` (Expo Router's home under a base URL is `/<slug>/`, and relative asset URLs resolved from the bare path miss the folder), `^/<slug>/$` proxies to the bare `<origin>/<slug>`, and `^/<slug>/(.*)$` proxies to `<origin>/<slug>/$1`. The home page goes to the bare path because a game built with `cleanUrls` (static output) serves its home at `/<slug>` and answers 404 at `/<slug>/`, which its `/:game/:path*` catch-all doesn't match: before 2026-10-18 the live Snake and LightCycles home pages were 404s through here (Solitaire's only worked from Vercel's cache). Every game serves the same page at the bare path, Hangman's single output included. `nuxt.config.ts` passes them as `nitro.vercel.config.routes`; Nitro's Vercel presets `defu` that config into `.vercel/output/config.json` with ours first (`nitropack/dist/presets/vercel/utils.mjs`, `generateBuildConfig`). Nitro's own `routeRules` can't do this: its Vercel output maps only `redirect` and `headers` rules, not `proxy`. A renamed game lists its old paths in `formerSlugs`, and each 308s to the same page under the new one (`/solitaire/play/klondike` to `/cardtastic/play/klondike`, since Solitaire became CardTastic on 2026-11-11), ahead of the game's own routes. Deploy order for a rename: the game's own deployment first, serving its export under the new path, then the hub.
- **Packs (2026-11-11):** a pack (DuelTastic, PuckTastic) lists its games in `games`, each with the page the pack's Home opens for it (`loadout/trap`). The card links each one under its description, and the sitemap lists them. A game that was an app of its own names its old path in `formerSlug`, and `/<formerSlug>` and everything under it 308 to that page (LightCycles to `/dueltastic/loadout/trap`, Snake to `/dueltastic/loadout/snake`, BoxHockey to `/pucktastic/loadout/boxhockey`), since its old pages have no counterpart in the pack; a rename keeps the path instead (`formerSlugs` above). Deploy order is the same: the pack's own deployment first, then the hub. The old games' Vercel projects are deleted once the hub forwards their paths.
- Each game builds its Expo web export under `/<slug>/` itself (its `experiments.baseUrl`, set only for web builds, and an output folder of `dist/<slug>`), so its own deployment serves `/<slug>/...` and the hub forwards paths unchanged.
- `origin` is each game's public production alias (`hangman-teal-psi.vercel.app` and so on). The `<project>-infinite-token.vercel.app` aliases answer 302 behind Vercel's login, so they can't be proxied.
- The Tastic game links are plain `<a href="/<slug>/">`, never NuxtLink: they leave this app. `nitro.prerender.ignore` keeps the crawler off them.
- `npm run dev` doesn't proxy the games. To try everything together locally, build the site (`NITRO_PRESET=vercel-static npm run build`) and serve `.vercel/output/static` next to each game's `dist/<slug>` with rewrites that mirror production.

## Deploy

`.github/workflows/ci.yml` is the shared `npm-ci.yml` (runs `verify`). `.github/workflows/deploy.yml` is JayDeaton-Web's: it deploys to Vercel on `v*` tags with `NITRO_PRESET: vercel-static`, and needs `VERCEL_TOKEN`, `VERCEL_ORG_ID`, and `VERCEL_PROJECT_ID` repo secrets. The Vercel project belongs in the **Infinite Token** team (`team_ZdxoV9u5tL6u8HSoIgNQuw1n`), with the game projects. Never create or change Vercel projects, domains, DNS, or secrets unasked.

A local `vercel build` or `NITRO_PRESET=vercel-static npm run build` leaves minified output in `.vercel/output/`, which ESLint then lints. Delete `.vercel/output` afterwards. Building locally with a different preset than the last build (`npm run build` after `verify`, then `NITRO_PRESET=vercel-static`) can prerender HTML with the previous build's ID while `_nuxt/builds/meta/` holds the new one, and skips the `_payload.json` files, so the pages 404 on them and log `NUXT_E5002`. Delete `.nuxt`, `.output`, and `node_modules/.cache` first. CI always builds fresh, so deploys aren't affected (seen 2026-10-17).

Lockfiles must be accepted by CI's npm 10. After `npm install` with the local npm 11, run `npx -y npm@10 install --package-lock-only`, or `npm ci` on CI fails with "Missing: ... from lock file".

HexFleet's online play (friends only for now; HexFleet's `ONLINE.md`, section 5) shares a match as `https://games.infinitetoken.com/hexfleet/join/<code>`. Where the game is installed, the link opens the match in it (a universal link on iOS, a verified App Link on Android) and this site never sees the tap; everywhere else it shows the invite page. - **The games:** `ONLINE_GAMES` in `site.ts` (HexFleet only so far): slug, icon, the preview image, the URL scheme, the bundle ID and Android package, where to get it (`get`, platform links, `'soon'` until there's a TestFlight public link and a Play test track, then the listings; HexFleet's `ios` is its App Store listing since 2026-11-24) and the Android signing keys' fingerprints. `APPLE_TEAM_ID` is Infinite Token LLC's team (6J8NCZC8G6, read off Jay's Apple Development certificate).
- **The page** (`src/pages/[game]/join/[[code]].vue`): the code in big letters with Copy (when the browser refuses the clipboard, the code is selected instead), Join the Match for a game with a web build on this site (any game in `TASTIC_GAMES`: `browserJoinPath`, `/<slug>/online?code=<code>`, since 2026-11-18), the platform chips, and Open (`hexfleet://join/<code>`), for someone who has the game but landed here anyway: iOS doesn't open an app from a universal link typed or pasted into Safari. It's `noindex` and left out of the sitemap, and every invite shares one preview (`public/images/hexfleet-invite.png`, rendered from `scripts/hexfleet-invite.html`, which reads the icon from HexFleet's repo beside this one): the message it's sent in names who sent it.
- **One prerendered page for every code:** `/hexfleet/join` is prerendered, and `inviteRoutes` (`src/utils/vercelRoutes.ts`, ahead of the game proxies so it still answers once HexFleet is on the hub) rewrites `/hexfleet/join/<code>` and `/hexfleet/join` itself to it, so neither goes to the game's proxy. `nitro.prerender.ignore` is a regex per game for the same reason: Nitro matches a string by prefix, and `/hexfleet` would have dropped the invite page from the prerender. Nuxt's router starts on the path a page was prerendered at and puts it in the address bar, which would lose the code, so an inline script in the page's head notes `location.pathname` before Nuxt runs (`window.__inviteOpenedAt`), and the page reads the code from that once mounted and puts the full address back.
- **The association files** are built from `ONLINE_GAMES` (`src/utils/appLinks.ts`) by server routes in `server/routes/.well-known/`, prerendered: `apple-app-site-association` (each game's app ID and `/<slug>/join/*`; Nitro's Vercel output gives the extensionless file `application/json` through `overrides`, so no header route is needed) and `assetlinks.json` (a game only once its fingerprints are in, so `[]` for now). Apple's CDN reads the iOS file when the app is installed, so a release of this site with it has to be live before friends install the build with the associated domain.

## Deleting online data (2026-11-18)

`/delete-data/hexfleet` (`src/pages/delete-data/hexfleet.vue`, `deleteDataPath` in `src/utils/appLinks.ts`) is the page Google Play's account deletion question needs: the steps in the game, the email route for someone without it, and what is deleted and what stays. It's in the sitemap and the prerender list through `ONLINE_GAMES`, so another online game needs its own page there or `seo.test.ts` and the build fail. It sits outside `/hexfleet/` on purpose: everything under that path goes to the game's proxy, the page's `_payload.json` included.

The privacy policy and this page state what Tastic-Server does, so check them against it when its data changes (`deletePlayer` in `src/matches.ts`): nothing expires on its own, anyone with a match's invite code can look up its seats' names, factions and colors (`lobby`), and a deleted player's matches stay with their name scrubbed and no player ID. Battles a device saved in its Battle History keep the names they were saved with: the server can't reach them.

They also state where the game puts Delete Online Data, so check them when that moves. Since 2026-11-23 they say each profile's Edit Profile screen (Settings, then the Profile row, or Profiles and the profile), deleting that profile's player, which is where HexFleet has had it since its build 11 (2026-11-20, `@tastic/profile` 0.25). It used to be in Settings, for every profile at once. CardTastic made the same move on main the same day, unreleased as of 2026-11-23 (v1.3.0 is the last tag), so the policy's CardTastic line still says "CardTastic's Settings": change it when that release ships.
