# Games-Web

The hub at https://games.infinitetoken.com, created 2026-10-17. It lists the Tastic games (Solitaire, Hangman, LightCycles, Snake, BoxHockey), Swirlio under More to Play, the ones coming soon, and the 6502 cartridges (A.C. Wright's Wizards Lab, then Snake and LightCycles; Pong is hidden for now), hosts the one privacy policy and support page for all of them, and puts every Tastic game's web version on this one origin at `/<slug>/`. The point of the single origin: localStorage is per origin, so only on one origin can the web games share player profiles the way the iOS apps do through the App Group `group.com.infinitetoken.tastic` (the web side of that lives in `@tastic/profile`). Before this, each game had its own subdomain (`<slug>.infinitetoken.com`); those now redirect here, from each game's own `vercel.json`.

## Stack and template

- Built from the `<Name>-Web` sibling template (JayDeaton-Web, GraPDF-Web, SnaPDF-Web, TrimBox, MapFolio): Nuxt 4 with `srcDir: 'src'`, Tailwind v4 through `@tailwindcss/vite`, the same eslint, vitest, tsconfig, CI, and deploy files. Keep that tooling converged with the siblings. **The look follows InfiniteToken-WWW instead** (2026-10-22, see Look below): it's the company's games site, not a page of jaydeaton.com. The accent is Tailwind's **indigo**, as on www.
- **Deliberate differences from the template:** no `@vite-pwa/nuxt` (a service worker scoped to `/` would also control the proxied games and could answer their navigations with this site's cached pages), so no `usePwa` either; no `@nuxtjs/color-mode` or safe-area shell (dark only, the window scrolls, as on www); and the class strings live in `src/constants/styles.ts` because four pages share them.
- Content is in `src/constants/site.ts` (`SITE`, `TASTIC_GAMES`, `CARTRIDGES`, `EMULATOR`); pages only render it. It is also the single source for the proxy routes and the prerender list in `nuxt.config.ts`, so adding a game is one entry there plus its image.
- Copy rules: Title Case headings, one-word buttons (Play, Source, Home), no em or en dashes anywhere (a test enforces it for `site.ts`).

## How the games are served

- `src/utils/vercelRoutes.ts` turns `TASTIC_GAMES` into Vercel Build Output API routes: `^/<slug>$` 308s to `/<slug>/` (Expo Router's home under a base URL is `/<slug>/`, and relative asset URLs resolved from the bare path miss the folder), `^/<slug>/$` proxies to the bare `<origin>/<slug>`, and `^/<slug>/(.*)$` proxies to `<origin>/<slug>/$1`. The home page goes to the bare path because a game built with `cleanUrls` (static output) serves its home at `/<slug>` and answers 404 at `/<slug>/`, which its `/:game/:path*` catch-all doesn't match: before 2026-10-18 the live Snake and LightCycles home pages were 404s through here (Solitaire's only worked from Vercel's cache). Every game serves the same page at the bare path, Hangman's single output included. `nuxt.config.ts` passes them as `nitro.vercel.config.routes`; Nitro's Vercel presets `defu` that config into `.vercel/output/config.json` with ours first (`nitropack/dist/presets/vercel/utils.mjs`, `generateBuildConfig`). Nitro's own `routeRules` can't do this: its Vercel output maps only `redirect` and `headers` rules, not `proxy`.
- Each game builds its Expo web export under `/<slug>/` itself (its `experiments.baseUrl`, set only for web builds, and an output folder of `dist/<slug>`), so its own deployment serves `/<slug>/...` and the hub forwards paths unchanged.
- `origin` is each game's public production alias (`snake-drab-kappa.vercel.app` and so on). The `<project>-infinite-token.vercel.app` aliases answer 302 behind Vercel's login, so they can't be proxied.
- The Tastic game links are plain `<a href="/<slug>/">`, never NuxtLink: they leave this app. `nitro.prerender.ignore` keeps the crawler off them.
- `npm run dev` doesn't proxy the games. To try everything together locally, build the site (`NITRO_PRESET=vercel-static npm run build`) and serve `.vercel/output/static` next to each game's `dist/<slug>` with rewrites that mirror production.

## Deploy

`.github/workflows/ci.yml` is the shared `npm-ci.yml` (runs `verify`). `.github/workflows/deploy.yml` is JayDeaton-Web's: it deploys to Vercel on `v*` tags with `NITRO_PRESET: vercel-static`, and needs `VERCEL_TOKEN`, `VERCEL_ORG_ID`, and `VERCEL_PROJECT_ID` repo secrets. The Vercel project belongs in the **Infinite Token** team (`team_ZdxoV9u5tL6u8HSoIgNQuw1n`), with the game projects. Never create or change Vercel projects, domains, DNS, or secrets unasked.

A local `vercel build` or `NITRO_PRESET=vercel-static npm run build` leaves minified output in `.vercel/output/`, which ESLint then lints. Delete `.vercel/output` afterwards. Building locally with a different preset than the last build (`npm run build` after `verify`, then `NITRO_PRESET=vercel-static`) can prerender HTML with the previous build's ID while `_nuxt/builds/meta/` holds the new one, and skips the `_payload.json` files, so the pages 404 on them and log `NUXT_E5002`. Delete `.nuxt`, `.output`, and `node_modules/.cache` first. CI always builds fresh, so deploys aren't affected (seen 2026-10-17).

Lockfiles must be accepted by CI's npm 10. After `npm install` with the local npm 11, run `npx -y npm@10 install --package-lock-only`, or `npm ci` on CI fails with "Missing: ... from lock file".
